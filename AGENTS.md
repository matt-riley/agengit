# Repository Guidelines

## Project Structure & Module Organization
`agit` is a Zig CLI for recording AI-agent session history into a local `.agit/` store. The entry point is `src/main.zig`, which wires top-level command dispatch and version output. Command implementations live in `src/cli/`, core persistence and snapshot logic live in `src/store/`, and shared platform helpers live in `src/util/`. Hook payload examples are kept in `src/fixtures/hooks/`. Architecture decisions are documented in `docs/adr/`; update or add an ADR when changing store format, hook behavior, durability guarantees, or release process.

## Build, Test, and Development Commands
Use Zig `0.16.0`.

```sh
zig build                         # build ./zig-out/bin/agit
zig build run -- version          # run the local CLI via the build graph
zig build test                    # run all Zig test blocks
zig build fmt                     # format src/ and build.zig
zig build check-fmt               # verify formatting, as CI does
zig build -Dtarget=x86_64-linux-musl -Doptimize=ReleaseSafe
```

## Coding Style & Naming Conventions
Rely on `zig fmt`; do not hand-align formatting against it. Keep modules small and purpose-based: new subcommands should usually be `src/cli/<command>.zig`, store primitives belong under `src/store/`, and cross-cutting OS helpers belong under `src/util/`. Follow existing Zig naming patterns: lowercase module filenames, `snake_case` locals/functions, and `PascalCase` types. When changing CLI behavior, keep `src/main.zig` usage text, README examples, and relevant tests in sync.

## Testing Guidelines
Tests are embedded with Zig `test "..."` blocks near the implementation they cover. Prefer focused tests for parsing, filesystem safety, idempotency, and error cases. Reuse or add JSON fixtures under `src/fixtures/hooks/` for agent hook payloads instead of hard-coding large payloads inline. Run `zig build test` before submitting; run `zig build check-fmt` after edits.

## Commit & Pull Request Guidelines
History follows Conventional Commit-style prefixes such as `feat:`, `fix:`, `docs:`, `ci:`, and `chore:`; release commits are generated by Release Please. Keep commit subjects imperative and scoped when useful, for example `fix: preserve user hooks during uninstall`. Pull requests should describe the behavior change, note any ADR or README updates, link related issues, and include validation commands run locally. For CLI output changes, include a short before/after snippet rather than screenshots.

## Security & Configuration Tips
Never commit `.agit/`, `zig-out/`, `.zig-cache/`, or local agent config files. Hook installers modify user-level Claude, Codex, and Gemini configuration, so tests should use temporary directories and fixtures rather than real home-directory files. Treat captured session data as private unless explicitly reviewed.

## Learned Rules

1. [PROCESS] Always target only top-level `.agit/tmp/*.json` files when an agengit test intends to corrupt a staging file — because recursive walks also see session turn-state files under `.agit/tmp/turns/` and can accidentally exercise recovery-turn behavior instead of corrupt-staging handling.
2. [PROCESS] When a command must inspect or rebuild store state without mutating refs/objects by default, do not route it through the default `Store.open` path unchanged — because `Store.open` auto-creates store dirs and reconciles index state on open unless you opt out explicitly.
3. [TEST] Always create a sandbox `.agit` directory before running hook-based e2e capture tests — because the hooks are fail-open, so missing repo setup can return exit code 0 while recording nothing and make assertions target the wrong behavior.
4. [ARCH] Always serialize destructive store maintenance with finalize-time snapshot/object/ref writes using `gc.lock` — because a preflight lock scan alone can still miss a new finalize and let gc prune deduplicated objects before the ref lands.
5. [TEST] In concurrent hook e2e tests, poll repo-visible counts until they settle instead of asserting immediately after child exit — because sanitized or highly contended runs can briefly report zero sessions/steps before `status` reflects the completed hook writes.
6. [ARCH] Always serialize fresh-store index initialization before concurrent hook opens — because multiple hooks can race through `Index.migrate` on an empty `.agit` store and fail-open on `schema_migrations` or table-creation conflicts.
7. [ARCH] When importing a conflicting session under a namespaced ref, also rewrite the imported step chain's `session_id` before indexing it — because `reindex` and `reconcile` derive session identity from step objects, not from ref filenames, so ref-only namespacing still collides on session/turn uniqueness.
8. [TEST] Always publish fake-server readiness files atomically in e2e helpers — because sanitizer runs can observe a just-created but still-empty readiness file and turn a helper race into a flaky CI failure.
9. [TEST] Always disable Git commit signing in e2e repositories that create commits (`git config commit.gpgsign false`) — because developer-global signing config can make sandbox commits fail or hang.
10. [ARCH] Always use SQLite insertion order rather than event timestamps as the internal cursor for live-follow queries — because late-finalized steps can have older display timestamps and would otherwise be skipped.
